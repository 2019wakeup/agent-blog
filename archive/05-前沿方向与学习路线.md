## 1. MCP 深入：协议生命周期、传输与安全

### 1.1 一个 MCP 会话的完整生命周期

```text
1. initialize 握手       客户端声明能力，Server 声明协议版本与能力
2. notifications/initialized  Server 确认
3. tools/list            客户端发现工具（可反复调用，Server 支持增量更新）
4. tools/call            客户端调用工具（每次一个 JSON-RPC 请求）
5. 资源同步              resources/list → subscribe → notifications（变更通知）
6. 关闭                  （客户端退出，stdio 管道关闭 / HTTP 连接断开）
```

### 1.2 三种传输方式的取舍

| 传输 | 适合 | 特点 |
|---|---|---|
| stdio | 本地子进程 | 最简单，进程级隔离；Agent 拉起 Server 子进程 |
| HTTP + SSE | 远程服务 | 传统流式，连接可复用 |
| Streamable HTTP | 远程服务（2025+ 主流） | 单一端点，双向流，云部署友好 |

### 1.3 MCP 的安全边界（企业必读）

- **信任模型**：MCP Server 的能力 = 你授予 Agent 的能力。接一个恶意的 MCP Server = 给 Agent 一个任意执行的后门；
- **审查清单**：只接可信来源的 Server；Server 用最小权限账号跑；敏感数据 Server 上做脱敏；所有 tools/call 留审计日志；
- **DSH 的做法**：MCP 工具进入 Agent 目录后，一样受沙箱/审批约束（第 4 篇 4.5 实战配置）。

## 2. 多 Agent 编排：从概念到可运行脚本

### 2.1 三种模式回顾

| 模式 | 结构 | 适用 | 风险 |
|---|---|---|---|
| Orchestrator-Worker | 一个调度者 + 多个 worker | 大批量独立子任务 | 调度者成瓶颈 |
| Handoff | 按技能转交 | 领域分明的流水线 | 转交链过长 |
| Debate | 互相质询 | 提高决策质量 | token 成本爆炸 |

### 2.2 DSH 的 Workflow：脚本化编排（可运行示例）

```js
// workflow 脚本（DSH 的 workflow 工具执行体，概念示例）
// 场景：多角度评审一份代码改动 —— 3 个独立 worker 并行评审 + 1 个汇总
const results = await parallel([
  () => agent('以「安全」视角评审这份 diff，返回结构化发现'),
  () => agent('以「性能」视角评审这份 diff，返回结构化发现'),
  () => agent('以「可维护性」视角评审这份 diff，返回结构化发现'),
])
const report = await agent(
  `汇总以下三份评审，去重合并，按严重度排序：${JSON.stringify(results)}`
)
return report
```

### 2.3 多 Agent 的成本铁律

多 Agent 的 token 成本线性叠加。**先单 Agent 跑通，按 ROI 加 Agent**；每次加 Agent 都要过评测（第 4 篇 4.7）。一个实用的升级路径：

```text
单 Agent（基线）→ 双 Agent（发现者 + 复核者，砍误报）→ 按需加 Worker（批量并行）
```

## 3. Agent 评测前沿：从基准到生产门禁

### 3.1 学术界基准（编码 Agent 的"高考"）

| 基准 | 测什么 | 注意 |
|---|---|---|
| SWE-bench / Verified | 修真实 GitHub issue 并过测试 | 编码 Agent 事实标准；Verified 子集去噪 |
| Terminal-Bench | 终端操作类任务 | 关注工具调用负担（2025-2026 热门） |
| OSWorld / WebArena | 桌面/网页交互 | 通用 Agent 能力 |

### 3.2 生产实践的五个共识（比基准更重要）

1. **领域评测集 > 通用基准**：把你团队真实历史 MR/issue 沉淀成评测集（第 4 篇 4.7 的做法）；
2. **可复现三件套**：固定模型版本、温度=0、评测集版本化；
3. **双层结构**：工具单测管正确性，E2E 评测管任务完成度；
4. **监控"悄悄变笨"**：模型供应商升级后必须先跑回归再放量——2026 年踩坑最多的点；
5. **成本也是指标**：通过率 × token 成本一起看。

## 4. 其他值得跟的前沿

- **上下文工程（Context Engineering）**：从"塞更多"到"精准投喂"——检索、摘要、KV 缓存友好的提示词组织，工程收益最大；
- **Agent 安全**：提示词注入（prompt injection）是头号威胁；防御 = 工具最小权限 + 输出过滤 + 内容隔离（DSH 的沙箱+审批即为此设计）；
- **工具生态**：MCP Registry 收录数千 Server，"应用商店"效应开始显现；
- **模型侧演进**：1M 上下文、更强代码推理、原生工具调用质量——模型变强会改变框架取舍（如 PTC 收益随模型编程能力提升而变大）；
- **Agent 记忆**：长期记忆从 RAG 走向"结构化记忆层"（entity/event 抽取），2026 年热门方向。
